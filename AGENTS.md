# AGENTS.md

## Project

lockstep (`lockstep`) is an offline drift guard for JavaScript and TypeScript projects. It reads a project and cross-checks every place a Node, Bun, or package-manager version is declared — `package.json` (`engines`, `packageManager`, `volta`), `.nvmrc`, `.node-version`, `.tool-versions`, `mise.toml`, the committed lockfile, and every `.github/workflows/*.yml` — then reports conflicts before you push. It is not a security scanner. Projects are read locally; there are no network calls and no telemetry. Output is text, stable JSON, or SARIF 2.1.0.

## Commands

- `bun install` — install dependencies.
- `bun test` — run the test suite in `tests/`.
- `bun run typecheck` — `tsc --noEmit`.
- `bun run make-fixtures` — regenerate the fixtures under `fixtures/`.
- `bun run build:site` — bundle `src/index.ts` into `site/assets/demo.js` (esbuild, IIFE, global `Lockstep`).
- `bun run check:site` — validate every `site/*.html`.

## Layout

- `src/` — implementation and the CLI entry point in `src/cli.ts`.
- `tests/` — `bun test` files.
- `site/` — static pages and `site/assets/` (styles, self-hosted fonts, the generated playground bundle).
- `scripts/` — `build-site.mjs` and `check-site.mjs`.

## Conventions and hard rules

- The site is fully static and offline: no external scripts or stylesheets, no network `src`, no telemetry.
- `site/assets/lens.css` is a shared design system copied byte-identical across the suite. Do not diverge it; per-tool changes go in `site/assets/theme.css`.
- `site/assets/demo.js` is generated by `scripts/build-site.mjs`. Edit `src/`, then rebuild; never hand-edit the bundle.
- `site/assets/fonts/*.woff2` are self-hosted Geist (SIL Open Font License 1.1). Do not swap them for a CDN.
- Every `site/*.html` must pass `bun run check:site`: exactly one `<h1>` and one `<main>`, a skip link whose `#fragment` matches an element id, and only classes defined in `lens.css` or `theme.css`.
- The CLI contract is stable: `lockstep [dir] [--dir <path>] [--json] [--quiet|-q] [--sarif <path>] [--fail-on <error|warning|info|none>] [-h|--help] [-v|--version]`. It audits one project per run (positional `dir` or `--dir`, default the current directory), and the exit codes are `0` (no findings at or above `--fail-on`), `1` (findings), `2` (invalid usage or unreadable input), `3` (I/O error).
- Rule codes are stable: `LOCK-001` through `LOCK-010`. Do not renumber or reuse a code.
